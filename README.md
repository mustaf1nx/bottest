# Telegram-бот с марковскими приветствиями

Бот встречает каждого нового участника группы или супергруппы уникальной
фразой, построенной цепью Маркова, и напоминает прочитать правила в описании и
гайд. На обычную переписку группы бот не отвечает.

> Telegram не отправляет ботам событие о новой подписке на обычный канал.
> Поэтому бот работает в группе/супергруппе либо в группе обсуждений,
> привязанной к каналу.

## Установка

Нужен Python 3.10 или новее.

```powershell
cd telegram_markov_bot
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

1. Откройте [@BotFather](https://t.me/BotFather), выполните `/newbot` и получите
   токен.
2. Вставьте токен в `.env` вместо примера.
3. Добавьте бота в группу. Отключать `Group Privacy` не требуется: события о
   новых участниках бот получает независимо от этого режима.
4. У бота должно быть право отправлять сообщения.
5. Запустите:

```powershell
python bot.py
```

После добавления бот сразу пишет `Бот подключён`. Если процесс бота в этот
момент не запущен, Telegram-сообщения обрабатываться не будут.

Команды:

- `/ops` — показать список всех ОП, Школ и назначенных администраторов;
- `/setopadmin <КОД_ОП> <@username>` — назначить администратора для ОП (доступно администраторам);
- `/setopchat <КОД_ОП> [chat_id]` — привязать чат ОП (проще всего выполнить прямо в чате нужной ОП); `off` вместо `chat_id` отвязывает;
- `/opchats` — показать все привязки и проверить права бота в них;
- `/preview` — тестовая генерация приветствия;
- `/allowpm` — выполнить в группе от имени администратора, чтобы открыть личные
  сообщения с ботом;
- `/id` — показать ID пользователя и текущего чата;
- `/start` — краткая справка.

Бот автоматически реагирует на упоминания Образовательных Программ (ОП) в сообщениях (как по коду: SE, BDA, CS и т.д., так и по полному названию: Software Engineering, Big Data Analysis и т.д.) и присылает карточку ОП с тегом соответствующего администратора. На обычные сообщения без упоминания ОП бот не отвечает.

Привязки ОП и администраторов хранятся в `op_admins.json`.

## Автоматический доступ в чаты ОП

### Главное ограничение Telegram

**Bot API не умеет добавлять людей в чат.** Метода вида `addChatMember` в нём
нет и не было: добавить участника может только обычный пользовательский
аккаунт. Поэтому «бот сам добавит человека по юзернейму» технически невозможно
без отдельного аккаунта-помощника (см. последний раздел). Юзернейм здесь ничего
не решает: бот и так знает `user_id` человека, а прав на добавление у него нет
ни с юзернеймом, ни без него.

Всё, что бот может легально, — выдать ссылку. Поэтому основной механизм
построен так, чтобы ссылка была безопасной сама по себе.

### Как это работает

1. Студент отвечает на приветствие кодом своей ОП.
2. Под карточкой ОП появляется кнопка «🔐 Вступить в чат». В её `callback_data`
   зашит `user_id` того, кому она адресована.
3. Если кнопку нажимает кто-то другой — бот показывает предупреждение и
   **не создаёт никакой ссылки**. Чужие нажатия логируются.
4. Своему владельцу бот создаёт **персональную ссылку** и отправляет её
   в личные сообщения. Если личка недоступна (человек не нажимал `/start`
   у бота) — ссылка уходит в общий чат ответом на его сообщение, с защитой
   от пересылки, и удаляется автоматически.
5. Человек переходит по ссылке → создаётся **заявка на вступление**.
6. Бот сверяет `user_id` заявителя с тем, кому ссылка выдана: совпало —
   одобряет, не совпало — отклоняет.

### Почему ссылка в общем чате безопасна

Ссылка создаётся с `creates_join_request=True`. Такая ссылка **не добавляет
в чат** — она лишь создаёт заявку, а решение принимает бот. Отсюда:

- ссылку можно скопировать, переслать, заскриншотить — постороннему это
  ничего не даст, его заявка будет отклонена автоматически;
- первая же чужая попытка **сжигает ссылку целиком** (отзыв + удаление
  сообщения), даже если она ещё не истекла;
- после успешного вступления ссылка сразу отзывается — она одноразовая;
- срок жизни 15 минут (`INVITE_TTL_SECONDS`), после чего ссылка отзывается,
  а сообщение с ней удаляется;
- на одного человека действует лимит выдач в час (`INVITE_HOURLY_LIMIT`);
- заявки по ссылкам, которые бот не создавал (например, сделанным вручную
  админом), бот не трогает — их по-прежнему рассматривают люди.

Сознательно **не используется** `member_limit=1`. Такая ссылка одноразовая, но
пускает в чат кого угодно, кто успел нажать первым, — именно тот риск, от
которого нужно защититься в большом чате.

### Настройка

1. Добавьте бота в каждый чат ОП и сделайте его администратором с правом
   **«Приглашать пользователей»** (`can_invite_users`) — без него бот не сможет
   ни создавать ссылки, ни одобрять заявки.
2. В чате ОП выполните `/setopchat SE` (подставьте свой код ОП).
3. Проверьте всё разом: `/opchats` — напротив каждой ОП должна быть ✅.
4. В общем чате первого курса боту полезно дать право **удалять сообщения** —
   тогда сообщения со ссылками будут исчезать сами.

Состояние выданных ссылок хранится в `invites.json` и переживает перезапуск.

### Опционально: добавление по юзернейму

Если нужно именно автоматическое добавление, потребуется аккаунт-помощник
(MTProto, Telethon) — см. `userbot.py`. Раскомментируйте `telethon` в
`requirements.txt` и заполните `TELETHON_API_ID`, `TELETHON_API_HASH`,
`TELETHON_SESSION`. Аккаунт должен быть админом чатов ОП.

Учтите риски, прежде чем включать:

- у большинства студентов стоит «добавлять меня могут только контакты» —
  Telegram вернёт `USER_PRIVACY_RESTRICTED`, и бот автоматически откатится
  к схеме со ссылкой;
- массовые добавления Telegram считает спамом: возможны `FLOOD_WAIT`
  и ограничения на аккаунт, поэтому используйте отдельный, не основной аккаунт;
- автоматизация пользовательских аккаунтов — серая зона правил Telegram.

Схема со ссылками-заявками работает и без этого, для всех одинаково,
независимо от наличия юзернейма.


## Настройка генератора

Добавляйте приветствия в `greetings.txt`, по одной фразе на строку, затем
перезапускайте бота. Строки, начинающиеся с `#`, считаются комментариями.

- `MARKOV_ORDER=1` даёт больше разнообразия, но менее связный текст.
- `MARKOV_ORDER=2` — рекомендуемый баланс.
- `MARKOV_ORDER=3` даёт более связный текст, но чаще повторяет исходные фразы.
- `MAX_GREETING_WORDS` ограничивает длину результата.

## Docker

Файл `.env` должен содержать действующий `TELEGRAM_BOT_TOKEN`. Токен не
копируется внутрь образа, а передаётся контейнеру только при запуске.

Сборка и запуск в фоне:

```powershell
docker compose up --build -d
docker compose logs -f bot
```

Остановка:

```powershell
docker compose down
```

Разрешённые через `/allowpm` администраторы сохраняются в именованном volume
`bot-admins` и не исчезают при пересоздании контейнера. Обычные сообщения группы
бот игнорирует; он реагирует только на добавление новых участников и команды.

Для кратковременных сбоев подключения к Telegram установлен увеличенный таймаут
и автоматические повторы отправки приветствия через 1 и 2 секунды.
